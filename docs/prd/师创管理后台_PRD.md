## 2. 项目概述

### 2.1 需求背景

师创管理后台为内部组织提供统一的业务工作入口，承载客户经营、产品研发、项目交付、审批与组织管理等协作流程。当前系统已形成多业务菜单和部分服务端数据能力；部分页面仍使用页面内演示数据，且历史入口兼容和业务规则待统一，需要以统一 PRD 明确页面边界、角色、状态、数据和验收口径。演示数据不得作为正式经营或验收数据。

### 2.2 需求价值与产品目标

| 目标类型 | 目标 | 可观察结果 |
| --- | --- | --- |
| 业务价值 | 统一客户、项目和合同信息 | 客户、商机、合同可关联查询，关键状态可追踪 |
| 交付价值 | 打通需求、任务、测试和缺陷协作 | 工作项可按产品线、版本和角色流转，历程可回溯 |
| 管理价值 | 统一审批、项目节点和经营指标 | 管理者可查看待办、风险、回款和交付进度 |
| 组织价值 | 维护员工、部门和业务权限基础 | 业务负责人、产品线成员和操作权限可配置 |
| 数据价值 | 保障真实数据和操作审计 | 刷新后数据保持一致，关键变更有活动记录 |

## 4. 业务流程与状态流转

### 4.1 总体业务流程

| 业务链路 | 起点 | 主要处理 | 结果 |
| --- | --- | --- | --- |
| 客户经营 | 线索或客户进入系统 | 建档、商机推进、拜访跟进、合同签订 | 客户和合同持续经营 |
| 产品交付 | 需求或协助事项 | 产品评审、拆分设计/研发/测试任务、版本规划 | 工作项完成并形成活动记录 |
| 测试质量 | 测试任务 | 选择用例、创建执行轮次、记录结果、关联缺陷、回归 | 形成测试结论和报告 |
| 项目交付 | 项目立项 | 里程碑、交付任务、风险和运维跟踪 | 项目节点可验收 |
| 综合审批 | 员工提交申请 | 部门审核、管理审批、结果反馈 | 申请形成可追溯结果 |

### 4.2 通用状态规则

| 状态类别 | 进入条件 | 可执行角色 | 可编辑范围 | 回退/结束规则 |
| --- | --- | --- | --- | --- |
| 草稿/待处理 | 新建或保存未提交 | 创建人 | 表单字段 | 可提交或继续编辑 |
| 处理中 | 负责人接受或开始处理 | 负责人、授权参与人 | 处理内容和进度 | 按配置流转 |
| 待验收/待审核 | 处理完成或提交审批 | 发起人、审核人 | 验收/审核意见 | 通过或退回 |
| 已完成/已关闭 | 通过验收或确认闭环 | 发起人、授权角色 | 通常只读 | 按业务规则重开 |
| 已驳回/已搁置 | 审核拒绝或主动搁置 | 发起人、负责人 | 原因和重开字段 | 重开范围待确认 |

### 4.3 跨模块规则

| 规则 | 业务要求 |
| --- | --- |
| 产品线范围 | 工作项类型、状态、成员和版本必须来自当前产品线 |
| 父子任务 | 存在未完成子任务时，父任务不得宣告完成；父任务完成后子任务不可继续修改 |
| 版本关联 | 版本中的需求、任务、缺陷和测试结果需能回到对应版本详情 |
| 审计记录 | 状态、负责人、审批、验收、删除和配置变更均需保留操作人和时间 |
| 并发控制 | 页面打开后的旧版本提交不得覆盖他人最新修改 |
