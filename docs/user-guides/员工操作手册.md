# 员工操作手册

> 本手册根据项目当前页面和业务逻辑整理，适用于当前版本。菜单、可见数据和可执行操作会受账号角色、组织关系、产品成员身份、记录状态及表单配置影响；看不到按钮或候选项时，不代表数据一定不存在。

## 使用前

登录后通过左侧导航进入对应模块。工作台、月度目标、复盘总结和协同事项位于“工作台”；产品管理、版本迭代以及产品/设计/研发/测试/缺陷工作项位于“产研管理”。售前任务、交付任务和运维任务位于各自的业务菜单。

列表常用流程是：先选产品或周期，再用搜索和筛选缩小范围，打开记录详情查看内容与操作。创建或修改后如遇失败，先看表单提示并确认必填项、权限和当前状态；加载错误可使用页面上的“重试”或“刷新”。

## 1. 我的待办

### 首页

“我的待办”首页展示四类指标：待办任务、协同事项、工单、待审批。下方待办卡片按类别筛选；卡片列表与审批列表展示最新 10 条。点击事项标题或卡片可查看详情；点击“查看更多”进入完整列表。

审批中心可切换“待我审批”“我已审批”“我申请的”“抄送我的”。“待我审批”只用于查看需要你处理的审批；是否能执行审批操作，还要看审批单状态和你的审批权限。

信息广场和产品动态卡片展示最新 10 条。打开动态详情后可查看正文；已读状态会记录阅读次数和最近阅读时间。部分动态的阅读统计只对有权限的人员展示。

### 完整待办列表

完整列表包含“任务”“协同事项”“工单”三个分类，不再提供“全部”分类。可以按标题搜索，并按类型、状态筛选；状态筛选包括未结束和已结束（含已完成）。每页最多显示 20 条，可分页查看。切换分类会清除先前分类的类型和状态筛选。

点击蓝色标题打开来源工作项详情。详情中的可操作按钮按本人是否为负责人、创建人以及事项当前状态显示。

### 代理商待办

进入“代理商待办”后，待办中心显示为“协同中心”，内容聚焦协同事项，不提供“全部、任务、协同事项”分类标签及待办类型/状态筛选。标题搜索仍可用于查找事项。

## 2. 月度目标

### 查看目标

1. 打开“月度目标”，在页面顶部选择目标月份。
2. 进入“目标 OKR”，用“我的目标”“上级目标”或“下属目标”切换查看范围；可点击目标名称查看 O、KR、权重、进度和变更记录。
3. 当前月份没有目标时，先核对月份及本人组织关系；普通员工需要有同月份、已确认的直属上级目标作为承接来源。

### 新增或修改目标

1. 在“目标 OKR”点击“新增目标”。填写目标（O）和至少一个关键结果（KR）。
2. 普通员工需选择同月份直属上级已确认的目标；可再选具体上级 KR。不选 KR 表示承接整个上级目标。组织根目标负责人不需要选择上级目标。
3. 每条 KR 填写名称及权重。KR 权重合计必须为 100%；至少保留一条 KR。不要为了通过校验而填写空白 KR。
4. 点击“保存草稿”。保存后回到目标列表，在记录上点击“提交”，送交主管确认。
5. 被退回的目标可修改后再次提交。上级确认后目标进入“执行中”；执行期间可更新 KR 进度。已确认目标的原计划日期受锁定规则保护，修改目标内容、承接关系或申请删除时，页面可能要求走审核。

目标状态常见为草稿、待主管确认、执行中、已退回、已确认/已完成、已归档。本人只能在允许的状态下修改或更新；列表没有对应操作时，请先查看当前状态或联系直属主管。

### 关联任务和事项

在“任务与事项”页查看本人负责的任务或工单，点击“关联 KR”，选择执行中的目标及其 KR 后保存。若清空目标，工作项会作为计划外工作保留；选了目标后还必须选择该目标下的 KR。已关联的工作可用于复盘归集。

## 3. 复盘总结

### 写周报或月报

1. 打开“复盘总结”，在“待填写”区域点击“写周报”或“写月报”。可填写的周期由系统复盘日期配置决定；按钮不可用时，先查看提示原因。
2. 按页面模板填写本期成果、目标/KR 进度、工作项产出、阻塞与影响、下期安排等内容。具体栏目会随周报/月报及员工/主管模板变化。
3. 检查自动归集的本期任务和协同事项。确认每项工作的成果、关联目标/KR；遗漏的工作可以按页面提供的关联功能补充，计划外工作也应如实记录。
4. 可先点“存草稿”稍后继续；确认无误后点“提交周报”或“提交月报”。页面若出现提交确认或校验错误，按提示补充后再提交。

同一周期已提交的复盘不能再作为新报告重复提交。草稿和已退回报告可在开放的周期内继续编辑；“可补交的”列表只显示符合当前补交策略的周期。提交后可在“最近提交的”或“查看全部”中打开查看。

### 主管查看与评价

主管在复盘页面切换到“待我评价 / 下属复盘”，查看员工已提交内容，按模板检查目标进度、工作成果和风险信息，并按页面要求评价或退回。退回时填写原因；若没有配置直属上级，复盘可能无法确定审批人，需要联系管理员维护组织关系。

## 4. 协同事项

### 发起事项

在“协同事项”点击“发起协同”，选择类型并按表单填写标题、负责人、描述及该类型的关联信息。常见类型与关键规则如下：

| 类型 | 主要必填信息 | 说明 |
| --- | --- | --- |
| 产品需求（客户诉求） | 标题、负责人、项目、产品、诉求来源、客户原始诉求 | “是否转产品”选“是”时，还需产品需求描述及期望完成时间；选“否”时隐藏期望完成时间，默认本人负责，可在创建后手动完成事项 |
| 线上问题 | 标题、负责人、项目、产品、期望完成时间、描述 | 严重程度可选；选择严重程度时会按规则联动优先级 |
| 售前支持 | 标题、负责人、商机、产品、期望完成时间、支持类型、描述 | 先选商机，再选其关联产品 |
| 交付支持 | 标题、负责人、项目、产品、期望完成时间、描述 | 产品候选随项目变化 |
| 其他协同 | 标题、负责人、协助类型、期望完成时间、描述 | 项目和产品选填；选择“数据支持”时默认匹配唯一有效的“鲍研”，仍可手动改选。若目录中找不到唯一匹配人员，按提示手动选择 |

优先级默认“中”，可以修改。项目/商机切换后若产品和负责人候选改变，应重新确认产品与负责人。提交按钮进入保存中状态时不要重复点击；保存失败时先看提示并保留页面输入重试。

### 处理与验收

1. “待处理”事项由当前负责人点击“事项接收”后进入处理中。只有当前负责人可处理接收、转交或退回等操作。
2. 处理中时，负责人可按需要创建关联任务。创建任务时确认负责人、说明、截止时间及“是否影响事项关闭”等信息；影响关闭的任务必须完成后，事项才能完成。
3. 负责人完成处理后提交事项结果，事项进入“待验收”。创建人检查结果后选择验收通过或验收未通过。
4. 验收未通过时填写整体反馈原因；该操作使协同事项回到处理中，不会自动修改关联任务状态或负责人。
5. 验收通过后事项完成。对退回事项，创建人可根据情况重新发起或关闭本次诉求；“关闭”表示本次诉求结束，不等同于负责人交付或验收通过。

仅记录型产品需求（是否转产品为“否”）创建后仍是待处理，不会自动完成；负责人可在待处理阶段手动点击“事项完成”。

### 退回原因参考

- 其他协同：事项内容不明确、不符合流程或者处理规范、重复提交、其他原因。
- 产品需求：项目部未把关/未预审、客户诉求不合理/非标准需求、超出合同/SOW 服务范围、缺少客户授权或必要附件凭证、已有替代方案/现有功能已支持、其他原因。

选择原因后还需填写详细说明；说明应写清需要补充或修正的内容。转派拒绝与事项退回是不同操作，拒绝转派需填写拒绝原因。

## 5. 产品管理

1. 打开“产研管理 → 产品管理”，可按产品名称/编码搜索，并按负责人、状态筛选；可切换卡片或列表视图。
2. 点击产品名称或产品卡片进入详情。产品详情提供基本信息、产品看板、版本管理、产品工时、产品效能、文档和产品设置等区域（可见区域可能随权限不同）。
3. 在产品看板查看当前产品的产品、设计、研发、测试及缺陷工作项分布；可以从看板的新建入口创建相应工作项。
4. 产品设置中的基本信息可维护产品名称和产品网址；产品编码为系统信息。责任配置展示产品、研发、测试和交付角色的主/次责任人，责任人可能影响新任务的默认负责人。
5. 产品使用结束时，产品操作中的“归档”会把产品从产品管理列表移至归档管理；归档前确认当前任务和版本安排。

产品列表中的版本管理入口会带入当前产品打开版本迭代。进入产品详情或任务列表后，先确认顶部/页面的产品范围，避免在错误产品下新增或修改数据。

## 6. 迭代版本

### 创建版本

1. 打开“产研管理 → 版本迭代”。可先选定产品，再点“新建迭代”；也可从产品详情的版本管理入口创建。
2. 填写所属产品、版本名称、版本号和版本负责人。预计开始/结束时间和版本内容/发版说明范围按计划填写；结束时间不能早于开始时间。
3. 保存后版本初始状态为“待开始”。进入版本详情查看版本工作项并关联相关任务。

### 维护迭代

- 版本详情/计划视图可查找、筛选、分组工作项，并按产品、设计、研发、测试、缺陷类别查看进度。为版本关联已有工作项前，确认所选产品与任务匹配。
- “待开始”版本点击“开启迭代”后变为“进行中”；进行中版本可点击“完成迭代”，状态变为“已完成”。完成操作不会把版本自动标记为“已发布”。
- 只有版本状态为“已发布”，或完成状态已带有发布日期等发布信息时，系统才会在产品动态中生成产品发布动态。单纯开启/完成迭代不等同于自动发布。
- 版本工作项可从迭代计划中打开详情、调整关联或进行批量操作。批量修改前核对选中项和目标版本，避免误改多条任务。

## 7. 任务工作项

### 类型与入口

常见工作项包括产品任务、设计任务、研发任务、测试任务和缺陷；业务任务菜单还包括售前任务、交付任务和运维任务。可以从对应菜单、产品详情看板或迭代计划进入。列表通常支持按标题搜索、产品/版本/状态/负责人等筛选，具体筛选项依页面类型而定。

### 新建与修改

1. 先选正确的产品（若从产品详情进入，产品通常已带入），再点击“新建”选择工作项类型。
2. 填写标题、任务类型、负责人、优先级、描述等页面字段；按工作需要补充关联项目、版本、计划时间、期望完成时间、预计工时、协同事项、关联任务、参与人和附件。字段的显示及必填要求由产品和当前工作项模板配置决定。
3. 选择系统提供的任务类型与状态，不要自行假定所有类型共用一套状态。若没有可用类型或新建提示状态流程未配置，请联系产品/工作项管理员维护模板和已发布流程。
4. 保存后在详情中查看负责人、状态、关联关系、评论和活动记录。详情支持的字段修改依权限和状态而定；状态变化如要求填写原因，应先补充原因再提交。

### 售前任务关联规则

售前任务类型包括标前工作、招投标工作、标后工作、售前宣发和其他；新建默认“售前宣发”。标前工作需关联商机并关联客户；招投标工作需关联招投标并关联客户。标后工作、售前宣发和其他类型的关联商机/招投标及客户为选填。切换任务类型后，确认关联来源字段对应的是商机还是招投标。

### 完成、验收与归档

- 工作项完成方式按该类型的状态流程执行；如页面要求完成原因、实际工时或其他信息，填写完整后再提交。
- 交付任务完成需由负责人发起；若创建人和负责人不同，会进入待审核，由创建人或管理员审核。通过后任务完成，退回后任务回到处理中。
- “归档”是从常规列表中收起记录的管理操作，不是恢复为待处理。点击归档前确认选中的工作项。
- 工作项任务完成与协同事项验收是两套状态流程：下游任务的完成不会自动替代事项创建人的验收操作。

## 常见问题

**看不到某个菜单或按钮怎么办？** 先确认当前账号、角色、产品成员身份和记录状态。部分操作只对负责人、创建人、主管或管理员显示；权限仍不匹配时联系系统管理员。

**列表里找不到刚创建的记录？** 清除搜索和筛选，核对产品、周期、创建人/负责人范围及分页；也可刷新列表。若保存时有错误提示，先确认是否实际保存成功，避免重复创建。

**提交/保存按钮不可用或报必填错误？** 按当前表单的星号字段、红色提示及日期/权重校验逐项检查。不同产品和工作项模板可配置不同字段，其他人的表单与自己的表单可能不完全相同。

**任务或版本为什么不能改状态？** 检查当前状态是否允许该操作、本人是否为负责人/创建人，以及任务类型是否配置并发布了状态流程。不要通过修改其他字段绕过状态流程。

**周报/月报不能填写或补交怎么办？** 查看按钮提示和系统填写日期配置。已提交周期不能重复新建；补交范围由复盘策略控制。

**产品动态里没有“开始迭代/完成迭代”消息？** 当前产品发布动态按已发布状态或发布信息生成；迭代开启或完成不会自动视为发布。

**目标显示待确认、复盘显示待评价怎么办？** 这是提交后的审核/评价状态，不代表提交失败。请等待直属主管处理；如审核人缺失，联系管理员检查组织关系。

**页面加载失败怎么办？** 使用页面“重试”或“刷新”；若仍失败，记录页面名称、操作步骤和提示文字，联系管理员或支持人员。
