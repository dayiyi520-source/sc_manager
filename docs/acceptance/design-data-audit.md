## 显示口径

| 对象 | 已确认的规则 | 待核对 |
| --- | --- | --- |
| 工作项优先级 | 存储 P0/P1/P2/P3，页面依次显示紧急/高/中/低；兼容已有中文和带后缀旧值；无法识别的值原样呈现，缺失显示未设置，不悄悄保存为 P2 | 各页面的历史值分布、异常值数量，以及四档颜色是否与设计最终稿一致 |
| 工作项状态 | 工作项绑定已发布的类型流程，展示流程中的名称与颜色；阶段用于统计，缺失显示未设置，不把五类任务的文案互相替换 | 历史状态与已发布流程不匹配的记录数、旧状态迁移规则 |
| 迭代状态 | 版本的未开始/进行中/已完成与工作项状态分开 | 历史版本状态及自定义模板的对应关系 |
| 协助事项、目标与总结、用例/执行/报告、评审 | 各用各自的数据源与状态规则，不继承工作项优先级或状态文案 | 实际数据库中的状态分布与各页面显示规则 |

## 场景矩阵

在林志豪、陈宇璋、毛景强三个体验视角下，逐页确认真实权限及可见范围；不预设三人的具体岗位或伪造跨角色可见数据。每人至少要有本人负责、本人创建、参与或相关但不负责的样例；哪些样例可见以现有权限为准。

| 页面 | 必需场景 | 关联验证 |
| --- | --- | --- |
| 我的任务、五类任务与缺陷列表 | 四档优先级、未开始/进行中/已完成/已取消、独立任务与有子任务的父任务、未分配和无版本的空态 | 创建/负责人/版本/状态修改后刷新仍一致；父子任务只展开显示，不全部铺开 |
| 产品详情、看板、迭代甘特图 | 多产品、多迭代，跨状态且有负责人、版本及计划起止日期的工作项 | 列表、看板、甘特图对同一工作项的状态与版本一致；无版本任务不得混进某一迭代 |
| 产品工时与效能 | 有预计、实际、完结和进行中数据；保留真实的未登记样例 | 汇总与明细可追溯；累计工时不冒充逐日工时 |
| 目标与总结、协助事项 | 三人各自可见的不同进度、协作角色与待处理/完成样例 | 负责人、创建人和关联任务保持一致 |
| 测试计划、用例、执行、报告、评审 | 未执行、通过、失败与回归轮次；关联缺陷；待评审和已评审 | 报告与评审来自实际执行结果，不能仅靠补充任务产生 |

## 实施顺序和门槛

1. 只读盘点本地租户的产品、版本、人员、工作项、协助事项、目标、用例、执行、报告、评审数量和字段缺口；分别统计异常优先级和未匹配的状态，不记录敏感字段。
2. 依据已发布流程确认状态映射及颜色。对状态归属无法唯一判断的旧记录保留原值并单列待确认，不自动改成“待处理”。
3. 在隔离的本地验收环境中建立可重复的场景数据，采用固定标识与幂等写入；先备份，再执行写入和跨页面验收。历史有价值数据仅定向修补，无价值演示数据也只在列清目标后清理。
4. 三人逐一切换，核对页面明细、权限、统计口径和刷新持久化。当前只完成本地工作项及部分关联表的只读盘点；验收环境隔离、事项与目标细节、场景生成和逐页浏览器验证仍未完成。
