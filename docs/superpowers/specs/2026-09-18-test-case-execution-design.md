# 测试用例与执行闭环设计

## 目标

在现有统一工作项体系上补齐测试用例库、测试计划、人工执行、多轮回归和缺陷追溯能力。需求评审下发的测试主任务继续作为统一工作项，测试人员通过类型化子任务完成用例编写和测试执行；主任务自动汇总子任务结果，不复制或替代子任务明细。

## 范围

- `测试与缺陷`增加“用例库”页签，保留现有“测试任务”和“缺陷管理”页签及缺陷业务逻辑。
- 测试用例按产品线独立维护，可记录来源需求，并被同产品线的不同需求、版本和测试任务重复引用。
- 测试任务创建界面区分主任务与子任务，继承并锁定来源字段。
- 测试任务详情根据主任务、用例编写子任务和可执行测试子任务展示不同内容。
- 可执行测试子任务提供测试计划、执行轮次、逐条结果、失败证据和多个关联缺陷。
- 测试主任务自动汇总子任务进度、用例、执行结果和缺陷。

本期不实现自动化脚本编排、CI/CD触发、跨产品线用例复用、参数化用例、公共步骤库、用例评审流和独立测试报告审批。

## 领域边界

### 统一工作项保持不变

现有测试分类及子类型继续使用：测试任务、用例编写、测试验收、安全测试、回归测试。它们仍是统一工作项，不把测试用例存入工作项表。

- 测试主任务：需求评审或人工创建的汇总容器，关联一个需求并继承产品线和版本。
- 用例编写子任务：表示设计、补充和维护用例的工作量，可创建或引用用例，不产生测试执行结果。
- 可执行测试子任务：测试任务、测试验收、安全测试和回归测试，可建立测试计划并执行用例。
- 测试用例：产品线级可复用资产，记录稳定的测试定义。
- 测试计划：某个可执行测试子任务选中的用例集合和执行安排。
- 测试执行：测试计划的一次执行轮次。
- 用例执行结果：某条用例在某次执行中的独立结果和证据。
- 缺陷：现有缺陷工作项，通过引用关系关联到失败结果、测试子任务和需求。

### 关系模型

```text
产品线
  └─ 用例库
       └─ 测试用例

需求
  └─ 测试主任务（来源字段只读、自动汇总）
       ├─ 用例编写子任务
       │    └─ 创建或引用测试用例
       ├─ 功能/安全/验收测试子任务
       │    └─ 测试计划 → 执行轮次 → 用例结果 → 缺陷
       └─ 回归测试子任务
            └─ 测试计划 → 执行轮次 → 用例结果 → 缺陷
```

测试用例长期归属产品线。来源需求只用于追溯首次创建原因，版本不作为用例的永久归属。测试计划和执行轮次记录本次使用时的需求与版本上下文。

## 页面与交互

### 测试与缺陷入口

页签顺序为“测试任务 / 用例库 / 缺陷管理”。

- 测试任务：继续使用统一工作项列表，增加测试专属创建与详情能力。
- 用例库：新增产品线级用例管理页面。
- 缺陷管理：保持现有列表、创建、详情和状态流转；只增加来自测试结果的引用展示与跳转，不重做页面。

产品线筛选器对三个页签保持一致。未选择具体产品线时，用例库允许汇总查询，但创建用例前必须选择一个产品线。

### 用例库

用例库采用左侧功能目录树、中央用例表格和可选右侧概览区。支持按编号或标题搜索，并按优先级、负责人和状态筛选。

列表核心字段为用例编号、标题、功能目录、来源需求、负责人、优先级、状态、最近执行结果和引用次数。点击用例进入详情，点击来源需求或引用任务跳转到对应详情。

新建和修改用例使用右侧抽屉，字段包括：

| 字段 | 规则 |
| --- | --- |
| 所属产品线 | 必填；创建后不可跨产品线迁移 |
| 用例标题 | 必填，去除首尾空白后保存 |
| 功能目录 | 必填，只能选择所属产品线目录 |
| 来源需求 | 选填；从需求下创建时自动带入且允许清除 |
| 优先级 | 必填，使用 P0-P3 |
| 负责人 | 必填，从团队组织有效员工选择并保存用户 ID |
| 前置条件 | 选填 |
| 测试步骤 | 至少一条，每条必须同时填写操作步骤和预期结果 |
| 标签 | 选填，用于筛选 |
| 状态 | 启用或停用；被引用的用例只能停用，不能物理删除 |

当前版本全部按人工用例执行。数据契约保留执行方式字段，但界面不提供会让用户误以为可以自动运行的自动化入口。

### 测试任务创建

人工创建测试主任务时，关联需求必填。选择需求后自动带入并锁定产品线和版本；标题、负责人、优先级、计划时间、描述、参与人和附件可编辑。需求评审自动下发的主任务直接使用评审结果创建，产品线、版本、需求和来源均不可由测试人员修改。

主任务下新建子任务时：

- 自动继承产品线、版本、需求和父任务，不提供重新挂接入口。
- 子任务类型只能选择该产品线测试分类下启用的类型。
- 负责人从产品线成员中单选。
- “用例编写”创建后进入用例维护流程。
- 测试任务、测试验收、安全测试和回归测试创建后可维护测试计划并执行。

### 测试任务详情

测试主任务详情显示“基本信息 / 子任务 / 汇总结果 / 关联缺陷”。基本信息中的需求、产品线、版本和下发来源只读。子任务可创建、查看和跳转；汇总结果按子任务实时计算，不允许人工填写汇总数字。

用例编写子任务详情显示“基本信息 / 关联用例”。测试人员可从产品线用例库引用已有用例，或新建用例并自动关联当前子任务，不显示执行记录和通过率。

可执行测试子任务详情显示“基本信息 / 测试计划 / 执行记录 / 关联缺陷”。

### 测试计划

每个可执行测试子任务维护一个当前测试计划。“测试范围”不再作为独立对象，测试计划中的已选用例集合即测试范围。

测试人员通过产品线用例库勾选用例；已停用用例不可新增，但历史计划继续展示。执行开始前可增删和排序用例。存在进行中的执行轮次时，计划仍可为后续轮次调整，但不得修改当前轮次已经生成的快照。

测试计划显示已选用例数量、负责人、环境说明和最近执行结果。空计划提供“选择用例”和“新建用例”入口。

### 测试执行

创建执行轮次时选择：

- 全部用例：复制当前测试计划的全部有效用例。
- 失败用例回归：复制上一轮失败的用例。
- 自定义范围：从当前计划中选择本轮用例。

执行轮次记录轮次名称、执行人、版本或构建号、测试环境、开始时间、结束时间和状态。创建时保存用例标题、前置条件、步骤和预期结果快照；后续修改用例库不会改写历史执行记录。

每条结果初始为未执行。人工执行后选择通过或失败：

- 通过：保存执行人和时间，实际结果选填。
- 失败：实际结果必填，至少允许上传截图、日志或文档证据；可创建新缺陷或关联已有缺陷。
- 同一失败结果允许关联多个缺陷。
- 已关联缺陷持续显示，再次创建时提示已有缺陷但不阻止新增。
- 结果保存后可继续下一条；已结束轮次只读，不覆盖或删除历史结果。

本期不增加“自动执行”按钮。自动化测试属于后续系统，通过脚本绑定和外部执行回传扩展。

### 执行记录和缺陷

执行记录是当前可执行子任务的轮次统计，展示总数、通过、失败、未执行、通过率、执行人、环境、构建版本和缺陷数量。各轮次独立保存。

关联缺陷页签只展示引用，点击跳转现有缺陷详情。由失败结果创建缺陷时自动带入所属需求、产品线、版本、测试主任务、测试子任务、执行轮次、用例标题、复现步骤、预期结果、实际结果和证据；测试人员补充标题、严重程度、优先级和技术负责人。

同一个问题已有缺陷时可搜索并关联，避免重复创建。技术修复后缺陷进入待回归；测试通过原用例后可将缺陷确认关闭，技术提交修复本身不自动关闭缺陷。

## 主任务自动汇总

测试主任务按全部直接和间接子任务实时汇总：

- 子任务总数、进行中数和完成数。
- 去重后的关联用例数量。
- 各执行轮次及最新轮次的通过、失败和未执行数量。
- 失败结果关联的去重缺陷数量及状态分布。
- 当前测试结论和不能完成的原因。
- 子任务负责人、预计工时和实际工时合计。

主任务来源字段不可由测试人员修改。主任务状态由系统协调：子任务开始后进入处理中；满足完成条件后自动完成。完成条件为所有必须交付子任务成功完成、最新有效执行不存在未执行用例、P0/P1未关闭缺陷为零。存在非阻断缺陷时允许完成，但测试结论显示“有条件通过”并保留未关闭缺陷数量。任一条件不满足时返回明确原因，不静默标记成功。

取消的子任务不视为成功完成；是否属于必须交付沿用统一工作项父子规则。已发布版本保持只读，不能新增计划、轮次、结果或缺陷关联。

## 数据模型

新增持久化对象：

- 测试用例：产品线、来源需求、目录、标题、前置条件、优先级、负责人、状态、修订号和审计字段。
- 测试用例步骤：用例、顺序、操作步骤和预期结果。
- 测试用例与工作项关联：记录用例编写子任务或其他测试子任务对用例的引用。
- 测试计划：与可执行测试子任务一对一，记录当前安排和修订号。
- 测试计划用例：计划与用例的多对多关系及顺序。
- 测试执行：计划、工作项、轮次、范围类型、环境、构建版本、执行人、状态和时间。
- 用例执行结果：执行轮次、用例、快照、结果、实际结果、执行人和时间。
- 执行结果附件：保存证据文件引用和审计信息。
- 执行结果缺陷关联：结果与缺陷工作项多对多关系。

所有业务表使用租户隔离、软删除、审计字段和乐观锁。产品线、需求、版本、工作项、人员和缺陷均保存 ID，名称只作为展示快照。核心关联使用关系表和外键语义，不使用 JSON 替代；历史用例内容快照可使用不可变结构化快照保存。

用例编号在租户和产品线内唯一。执行轮次编号在测试计划内唯一。计划用例、工作项用例和结果缺陷关系均建立组合唯一约束，重复请求不得生成重复关系。

## API 契约

### 用例库

- 分页查询支持产品线、目录、关键词、优先级、负责人和状态筛选。
- 创建请求包含产品线、来源需求、目录、标题、前置条件、优先级、负责人、步骤和标签。
- 修改请求必须携带修订号；并发冲突返回 409 并提示刷新。
- 停用接口幂等；已被计划引用时保留历史记录。
- 目录查询按产品线返回树和各节点用例数量。

### 测试计划与执行

- 查询测试详情时返回任务角色、是否可执行、测试计划摘要、轮次摘要、缺陷摘要和主任务聚合结果。
- 保存计划请求包含修订号和有序用例 ID；后端校验租户、产品线、任务类型、用例状态和版本可编辑性。
- 创建执行请求包含幂等请求标识、范围类型、可选用例 ID、环境和构建版本。
- 保存结果请求包含执行结果修订号、结果、实际结果和证据引用；失败结果必须包含实际结果。
- 创建或关联缺陷请求包含执行结果修订号；后端同时写入结果缺陷关系和现有工作项 `FOUND_DEFECT` 关系。
- 结束轮次前返回未执行数量；存在未执行用例时要求用户明确继续执行，不允许假报全部完成。

所有接口返回稳定错误语义：参数错误、无权限、数据不存在、跨产品线、状态冲突、并发冲突和已发布版本只读。Controller只处理输入输出，业务校验、事务和聚合由Service负责。

## 状态与权限

用例状态为启用、停用。执行状态为未开始、执行中、已结束、已取消。用例结果为未执行、通过、失败；本期不增加会改变主流程的阻塞和跳过结果。

超级系统管理员可维护全部产品线用例和测试数据。后续权限扩展时，以产品线成员和负责人范围为基础，不把员工是否拥有登录账号作为用例负责人有效性的判断条件。

危险操作使用 Ant Design 确认弹窗和消息反馈，不使用浏览器原生弹窗。保存、创建轮次和转缺陷期间显示加载状态并防止重复提交。网络错误保留表单输入和未上传证据清单，允许重试。

## 异常与边界

- 需求未归属产品线或版本时不得创建测试主任务，并提示回到需求补全。
- 子任务与父任务产品线、版本或需求不一致时拒绝保存。
- 跨产品线用例不可加入计划，不能通过直接提交 ID 绕过。
- 用例步骤为空、只有操作没有预期结果或顺序重复时拒绝保存。
- 用例停用后不能加入新计划，已有执行快照仍可查看。
- 用例在计划保存后被修改时，新轮次使用最新版本；已创建轮次使用自己的快照。
- 同一轮次不得重复加入同一用例；同一缺陷不得重复关联同一结果。
- 失败结果没有实际结果时不能保存；附件失败不应显示上传成功。
- 多人同时执行同一条结果时使用修订号检测冲突，后提交者刷新后再处理。
- 已结束或已取消轮次禁止修改结果；恢复必须记录审计事件。
- 长标题、长步骤和大量用例使用省略、完整查看、分页或虚拟滚动，不能撑破布局。

## 视觉与组件状态

遵循现有 AIEDIT 暗色 Design Token、8pt 栅格和 Ant Design 主题。使用 Octicons/现有图标兼容层，不新增图标库。页面保持高密度工作台结构，不使用营销式大卡片或装饰渐变。

新增列表、抽屉、计划选择器、执行器和结果页必须覆盖：正常、悬停/聚焦、加载/执行中、禁用/错误/空数据状态。测试执行页面优先展示当前用例、步骤、通过/失败操作和证据；辅助统计与关联缺陷位于次级区域。默认浏览器验收视口为 1920×1080，同时验证窄屏横向滚动和抽屉可操作性。

## 验证与验收

- 前端组件测试覆盖新增页签、产品线筛选、用例创建校验、计划勾选、执行范围、多轮结果、失败证据、多个缺陷关联、只读主任务和错误恢复。
- 后端单元及集成测试覆盖租户和产品线隔离、ID归属、步骤持久化、计划并发、执行快照、幂等创建、结果状态机、多个缺陷关系、已发布版本只读和主任务聚合。
- 数据库迁移验证新环境初始化、已有环境升级、唯一约束、索引、软删除和重复执行策略。
- 浏览器按 1920×1080 验收测试任务、用例库、新建用例、测试计划、测试执行、执行结果和缺陷跳转；同时检查加载、空数据、错误和禁用状态。
- 完整链路验收：需求评审下发主任务 → 创建用例编写及测试子任务 → 产品线用例库创建用例 → 测试计划引用 → 第一轮执行失败 → 一个结果关联多个缺陷 → 技术修复 → 失败用例回归 → 主任务自动汇总并形成通过或有条件通过结论。
