# 目标与绩效闭环设计规格

## 目标

将目标与绩效从前端演示型的独立填写，升级为“上级目标引用、下级 OKR 拆分、任务与工单支撑、计划外工作补充、周期复盘、主管评价”的闭环。

## 业务规则

- 下级创建 OKR 必须引用一个可见的上级目标或 KR。
- 下级只能引用和拆分上级目标，不能修改上级内容。
- 本次实现一个直属上级主关联；多目标协同关联保留为后续迭代。
- KR 权重合计必须为 100%，进度范围为 0 至 100。
- 任务、需求、研发任务、缺陷和工单可以关联到 OKR 或 KR。
- 未关联 OKR 的计划外工作必须进入复盘，可记录其对目标延期的影响。
- 计划外工作是否计入正式绩效由主管确认。
- 复盘内容以本周期 OKR、任务和工单结果为主体，文字总结用于归纳。
- 复盘支持提交、主管评价、退回修改、重新提交、确认和归档。

## 用户流程

员工选择周期并引用上级目标或 KR，填写个人目标和 KR，提交主管确认；执行过程中更新 KR 进度并维护任务、工单关联；周期复盘自动汇总 OKR 内工作和计划外工作，员工补充结果、阻塞和影响后提交；主管检查交付证据，评价 KR 与计划外贡献，确认或退回复盘。

## 领域关系

```text
组织目标 → 部门目标 → 个人目标 → KR → 任务 / 工单
                                      ↘ 计划外工作 → 复盘影响说明
```

核心对象包含 Objective、KeyResult、WorkItemObjectiveLink、PerformanceReview、ReviewWorkItem，并保留状态、审核人、版本和审计信息。

## 页面范围

- OKR 列表、目标详情、引用上级目标面板、目标关系视图。
- 工作项与工单的 OKR/KR 关联入口。
- 结构化复盘工作区、计划外工作区、主管评价面板。

## 异常与边界

- 上级目标已关闭、被删除或当前用户无权限时禁止引用。
- 周期无目标、无关联工作项或无计划外工作时显示可恢复空状态。
- 请求超时、网络中断、重复提交和并发修改需保留表单内容并提示重试或刷新。
- 目标引用、KR 权重和状态变更必须由后端再次校验。

## 验收标准

- 下级无法绕过上级引用要求提交 OKR。
- 复盘可显示本周期 OKR 内任务、工单和计划外工作。
- 计划外工作可标记其对延期 KR 的影响，并由主管确认是否计入绩效。
- 主管可退回复盘，员工修改后重新提交。
- 刷新页面后业务数据仍可恢复，权限范围符合角色关系。
