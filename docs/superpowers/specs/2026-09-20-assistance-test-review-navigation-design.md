# 协助事项、测试任务与版本评审重组设计

## 1. 目标与范围

本次调整统一工作台事项术语，重组产品管理中的测试与缺陷入口，并新增可持久化的版本评审能力。

范围包含：

- 工作台用户可见文案由“工单”统一调整为“事项”，入口名称改为“协助事项”，创建入口改为“发起协助”，列表入口改为“事项列表”。
- 产品管理将“测试与缺陷”拆分为“测试任务”和“缺陷管理”两个独立菜单。
- “测试任务”页面保留测试任务与用例库，并新增测试报告 Tab。
- 产品管理新增“版本评审”菜单，支持评审草稿的新增、编辑、保存、提交和持久化。
- 现有版本详情继续使用相同的测试报告能力，不复制第二套业务实现。

产品复盘、产品规划和产品自动化规则不在本次调整范围内。

## 2. 信息架构

### 2.1 工作台

- 侧栏入口：协助事项。
- 页面主 Tab：发起协助、事项列表。
- 页面内用户可见的“工单”统一替换为“事项”，包括标题、按钮、字段说明、成功与失败反馈、空状态、详情和流转提示。
- 后端接口路径、数据库字段、TypeScript 类型名等内部兼容标识保持不变，避免无业务价值的破坏性迁移。

### 2.2 产品管理

产品管理菜单新增或调整以下独立入口：

1. 测试任务：包含“测试任务”“用例库”“测试报告”三个 Tab。
2. 缺陷管理：直接展示现有缺陷统一工作项页面，不再作为测试任务页面的 Tab。
3. 版本评审：展示独立的版本评审工作区。

菜单刷新、标签页恢复和直接访问均使用稳定页面标识，不通过跳转参数模拟独立菜单。

## 3. 测试报告工作区

测试报告继续复用现有版本测试报告面板。测试任务页面中的测试报告 Tab 在面板上方提供：

- 产品线选择，仅展示当前用户可访问的产品线。
- 版本选择，随产品线联动，仅展示所选产品线的有效版本。
- 未选择产品线时禁用版本选择和报告操作。
- 产品线没有版本时展示明确空状态，不允许创建报告。
- 切换产品线时清空不再有效的版本选择和当前报告详情。
- 加载失败时保留当前选择并提供重试，不展示伪造或本地回退数据。

版本详情中的测试报告子 Tab 保持现有入口，直接向同一报告面板传入已确定的产品线和版本。

## 4. 版本评审业务模型

### 4.1 字段

每条版本评审包含：

- 所属产品线
- 版本
- 评审日期
- 参与人
- 评审结论：通过、有条件通过、不通过
- 评审摘要
- 遗留风险
- 发布建议
- 状态：草稿、已提交
- 创建人、更新人、创建时间、更新时间
- 乐观锁版本号

参与人必须从当前租户的在职员工中选择。产品线和版本必须存在、未删除且归属关系一致。

### 4.2 状态规则

- 新增评审默认保存为草稿。
- 草稿允许编辑和反复保存。
- 提交前必须填写评审日期、至少一名参与人、评审结论和评审摘要。
- 已提交评审只读，不允许再次编辑或重复提交。
- 同一版本允许保留多条历史评审，以支持复审，不覆盖已提交结论。
- 并发修改使用乐观锁；客户端版本过期时返回冲突并要求刷新。

### 4.3 页面流程

版本评审页面先选择产品线和版本，再展示该版本的评审列表。用户可以：

1. 新建草稿。
2. 编辑已有草稿。
3. 保存草稿。
4. 提交草稿。
5. 查看已提交评审详情。

第一视觉焦点是产品线和版本上下文，第二视觉焦点是评审列表与新增操作，编辑区域使用现有抽屉或页面表单模式并遵循项目 Design Token。

## 5. 后端与数据设计

新增版本评审业务表，遵循现有租户、审计、软删除和乐观锁字段规范，并通过版本化 SQL 迁移创建。建议索引覆盖：

- 租户、产品线、版本、软删除的列表查询。
- 租户、版本、状态、评审日期的历史查询。
- 租户、创建人、状态的草稿查询。

后端调用方向保持 Controller → Service → Mapper → Database：

- Controller 处理 HTTP 输入、权限声明和响应。
- Service 校验租户、产品线访问权限、版本归属、在职参与人、状态和乐观锁，并管理事务。
- Mapper 只负责评审记录的查询、写入和状态更新。

接口能力包括：按产品线和版本查询、新增草稿、查询详情、更新草稿、提交评审。所有返回对象仅包含页面需要的字段。

## 6. 权限与一致性

- 读取评审需要产品模块读取权限和对应产品线访问权。
- 新增、编辑和提交需要产品模块写权限和对应产品线写权限。
- 所有查询和写入必须携带当前会话租户边界。
- 已提交记录不可修改；软删除记录不可读取或更新。
- 更新和提交必须同时校验记录版本号，避免后写覆盖先写。
- 提交评审与状态更新在同一事务中完成，不产生半提交数据。

## 7. 异常与边界状态

至少覆盖以下边界：

1. 无可访问产品线或所选产品线无版本：展示空状态并禁用创建。
2. 网络断开或请求超时：保留选择和表单草稿，不提示成功，允许重试。
3. 长文本：摘要、风险和建议限制长度并保证列表省略、详情完整可读。
4. 参与人被停用：保存或提交时拒绝并指出无效参与人。
5. 版本已删除、跨产品线或不可访问：拒绝查询和写入。
6. 并发编辑：过期版本返回冲突，页面保留草稿并提示刷新。
7. 重复提交：已提交记录再次提交返回冲突，不新增重复记录。

## 8. 前端状态与交互

新增和调整的交互均覆盖：

- Normal：展示当前选择、列表和可用操作。
- Hover / Focus：遵循现有 Ant Design 主题令牌和焦点反馈。
- Active / Loading：查询显示加载态，保存和提交期间禁用重复操作。
- Disabled / Error：无上下文、无权限、空数据、网络失败和校验失败提供明确反馈。

页面不使用前端 Mock 作为生产数据回退，所有写操作仅在后端确认成功后更新页面和显示成功消息。

## 9. 测试与验收

### 9.1 前端

- 菜单名称、页面标识和直接访问正确。
- 协助事项页面的用户可见术语完整替换，内部接口契约不变。
- 测试任务页不再出现缺陷管理 Tab，新增测试报告 Tab。
- 测试报告的产品线、版本联动和空状态正确，并复用现有报告面板。
- 缺陷管理菜单直接展示缺陷统一工作项页面。
- 版本评审草稿保存、提交、只读、失败保留和并发冲突反馈正确。

### 9.2 后端

- 版本评审新增、查询、更新、提交持久化通过。
- 必填字段、版本归属、参与人在职状态和状态机校验通过。
- 跨租户、无权限、软删除、过期版本和重复提交均被拒绝。
- 已提交记录不可修改，多次评审可作为独立历史记录存在。

### 9.3 回归

- 现有版本详情测试报告功能保持可用。
- 产品复盘、产品规划和产品规则不发生行为变化。
- 前端构建、相关定向测试、后端全量测试和 PRD 校验通过。
