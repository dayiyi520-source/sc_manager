# 五类工单中心设计

## 目标

将工单中心改造为五类工单入口，并让创建、列表、详情和流转保持统一体验，同时兼容已有历史需求记录。

## 方案

在现有 RequirementTask 上增加 `workOrderType` 与 `specialFields`，保留 `taskType` 用于历史数据和下游工作项映射。新工单类型为客户诉求、线上问题、售前支持、交付支持、其他问题。提工单页先展示五张入口卡片，选中后渲染公共字段和该类型专属字段；提交后统一进入列表。

列表按五类工单分别展示总数、待处理、处理中、已处理，支持类型 Tab、标题/客户/负责人搜索、与我有关范围和状态筛选。详情继续使用现有抽屉和流转历程组件，并按类型展示专属字段。

## 数据契约

公共字段：标题、富文本描述、负责人、优先级、期望完成时间、关联客户。

专属字段：客户诉求（所属项目、类型、诉求来源）；线上问题（关联产品、严重程度、发生频率）；售前支持（关联商机/线索、支持类型、预计时长）；交付支持（关联项目、交付阶段、服务级别）；其他问题（问题类型、问题来源、期望结果）。

`workOrderType` 缺失时按历史 `taskType` 展示旧记录；`specialFields` 缺失时详情展示“未补充”。

## 边界

- 未选择工单类型不能进入表单。
- 公共必填字段缺失时阻止提交并保留输入内容。
- 关联数据加载失败时保留可输入控件并提示重试，不阻止查看已有列表。
- 历史记录无新类型字段时仍可查询、详情和执行原有流转。
- 空列表和统计零值正常展示，不隐藏筛选条件。
