# 协同事项流程修复计划

用户已确认流程：处理中负责人可在详情上方新建五类任务；已退回创建人可关闭或重新编辑；验收未通过只更新事项状态，选填关联任务作为原因反馈；负责人默认来自最近实际处理记录；已完成重开进入同一编辑表单并在描述附件后填写独立重开原因。

1. 提取 collaborationWorkflow 工具，稳定匹配创建人并恢复最近实际处理负责人；覆盖新身份、历史姓名、人员失效、同名及重复验收循环。
2. WorkItemCreatePanel 的新建工作区挂载 body Portal 并使用已有浮层层级，使协同详情上方的新建可见可操作；验证五类菜单、取消、成功回到详情。
3. RequirementPoolView 回填现有创建表单用于退回重编和完成重开；取消与失败保留原业务状态；提交统一待处理，原编号与关系不变。事项关闭用独立确认弹窗，更新完成并记录关闭原因语义。
4. 复用现有 /transition、/reopen、/acceptance-failed 路由并在 repository 明确新入参：关闭含 action close + revision；重发含编辑字段 + assigneeId + revision，已完成必须 reason；验收失败含必填 reason、可选 workItemId、有效原处理人 taskOwnerId + revision。生产后端本仓库未提供，变化为显式待联调契约，不能以拆分更新掩盖原子性需求。
5. 本地 Mock 以独立处理模块校验状态、创建人、有效人员、版本和输入，白名单保存编辑字段。完成时记录实际处理身份。验收失败不写任何任务存储和状态，反馈快照写入事项历程。保存和历程同步原子落盘。
6. 更新1.2.44与1.2.45 PRD：替换旧验收任务状态修改、直接重开及退回完成规则；保留历史编号。运行相关服务及UI测试、TypeScript、build、PRD校验与1920x1080本地浏览器验证。

边界：无关联任务、不同负责人任务、原处理人失效、空原因、长原因、重复提交、版本冲突、取消编辑、字段回填、关联对象失效。当前共享PRD及mockApi含其他用户改动，保留且不混入checkpoint。

## 描述回填与运维、设计入口补充

用户要求：退回重编和完成重开均回填详情已有描述并可局部修改；关闭确认文案按用户原文；新增任务下拉增加运维在交付后；产品需求对应产品设计、项目交付对应项目设计、其他对应其他设计。

直接原因是主描述编辑器缺少value/htmlValue；接入已回填状态，不改编辑器依赖。测试HTML及文本回显、产品需求附加描述、附件保留、局部修改和取消；创建入口验证六类顺序及类型映射和新建参数。项目/其他设计来源默认使用已关联项目/部门，不能把产品名填成项目名。无项目仍打开表单补选。更新1.2.45并运行相关测试、typecheck、build、PRD校验及标准视口预览。
