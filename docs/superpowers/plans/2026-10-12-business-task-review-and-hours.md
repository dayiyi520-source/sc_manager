# 业务任务审核与工时分布 Implementation Plan

**Goal:** 固定运维、售前、交付任务字段，补齐交付审核流程，隔离业务任务与工作项模板，并让产品工时分布有可用 Mock 数据。
**Architecture:** 业务任务继续使用独立状态与业务接口；统一工作项状态仅服务产品、设计、研发、测试和缺陷。新增交付审核状态与操作契约，Mock 层持久化状态变化和审核事件。工时图使用任务计划日期与预计工时聚合。
**Tech Stack:** React、TypeScript、Ant Design、Vitest、Vite。
**Spec:** 用户确认的本次需求与 docs/prd/V1.0.0.md。

## Global Constraints
- 不把运维、售前、交付加入工作项模板或产品详情产品配置。
- 列表字段按用户要求保留或调整，详情字段不由旧工作项字段配置控制。
- 状态变更和审核操作必须通过既有 API 层及 Mock API，不在页面直接写 fetch。
- 保留工作区其他未相关修改。

## Tasks
- [ ] 核对并统一统一工作项状态来源，补齐 Mock 状态模板和状态选项测试。
- [ ] 固定运维、售前、交付任务字段与关联项，补充交付待审核 Tab、主管通过/驳回。
- [ ] 过滤业务分类，避免工作项模板和产品配置显示运维、售前、交付。
- [ ] 补充产品工时计划日期与预计工时 Mock，验证时间分布图聚合。
- [ ] 更新 PRD，运行相关测试、类型检查和构建。
