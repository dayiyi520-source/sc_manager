# Unified Work Item Storage Implementation Plan

**Goal:** 第二批交付真实统一核心存储、测试工作项、分类流程版本与子任务配置，提供可验证接口。

**Architecture:** 沿用当前 JdbcTemplate 分层，不改变依赖；核心表承载新工作项，旧业务表继续只读兼容。流程以不可变发布版本保存完整状态与边定义，草稿允许带版本号修改；同一产品线的配置写入及工作项创建锁定产品线记录，防止停用与创建竞争。

**Spec:** `docs/superpowers/specs/2026-09-14-unified-work-item-model-design.md`

## 执行范围
- 新增 `V20260914.1__unified_work_item_storage.sql`：统一核心、流程版本、父子类型规则、活动记录；不搬旧数据，不自动绑定历史自定义状态。
- `WorkItemDefinition`：分类映射、流程节点、流转定义、创建输入契约和校验。
- `WorkItemStorageMapper`：固定参数化 SQL、行锁、版本比较、幂等查询及审计持久化。
- `WorkItemConfigurationService/Controller`：分类流程草稿、发布、父子类型规则；拒绝修改已发布版本。
- `WorkItemStorageService/Controller`：创建/读取新工作项、查询活动；所有新工作项绑定启用类型和已发布分类流程。测试与其他分类采用同一核心表。
- `UnifiedWorkItemMapper/Service`：把核心记录纳入统一列表，读取绑定流程属性，不把自定义完成状态当作未知。
- `ProductLineService/Mapper`：类型配置补充测试分类，已用类型禁止删除或换分类，仍可停用。
- 同步 PRD 1.1 和本地验收说明，不改线上配置或 OKR 工作树。

## 验证与交付顺序
1. 先通过纯单元测试检查流程图初始节点、成功终态、非法边、不可达节点和分类隔离。
2. 使用现有本地连接进行只读预检，核对 Flyway 最大版本、旧表数量和新表不存在状态；保存本地备份后追加迁移。
3. 事务回滚集成测试验证发布不可改、乐观锁冲突、已用类型保护、重复创建幂等、跨租户/产品线拒绝、已发布版本只读、子任务继承和活动记录。
4. 打包后替换本项目后端运行包，复用前端和端口，保留版本修复能力；提供接口阶段验收说明。

## 明确边界
状态执行、评审原子下发、依赖闭环和前端配置界面是下一批。本批流程配置可发布、任务可真实创建，但不开放跳转接口。历史数据不自动迁移；发布资格仍返回不可判定。迁移不删除表，应用回退保留新表和业务数据。
