# 三级月度目标补全

**Goal:** 在现有添加、列表、卡片和详情样式上补全三级承接、本人执行动作、修改审批与时间基准。
**Architecture:** 扩展现有 OkrPayload/OkrKr；新增纯业务规则和独立 Mock 生命周期处理器；使用现有 ObjectiveForm 和目标详情容器，追加 KR 类型选择、本人 A 与审批反馈。只读上级源引用不复制为可编辑个人 O。生产模式沿用 API 层，不隐式回退本地数据。

- [x] 数据：goalModelVersion、goalLevel、sourceObjectiveId/sourceKrId/sourceVersion、继承占位；KR structureType（三类）与 executionActions（本人 A）；plan/forecast/actual 时间；changeRequest 和来源同步版本。
- [x] 承接：主管仅承接指派自己的公司 KR；员工仅承接指派自己的部门 KR；同一月份来源去重，未承接自动显示待填写条目，上级上下文按需查看。
- [x] 表单：公司 O/KR 纯文本；主管编辑指标 O、按需选三类 KR；本人 A 无指派；员工 KR 标题只读，直接编辑 A。
- [x] 生命周期：主管修改由上级审批；员工修改由主管审批；公司直接生效但标记下级待同步；审批失败不改变生效正文，原计划日期锁定、预计延期需原因，记录审核与完成时间。
- [x] 展示：复用列表/卡片/详情结构、新增子动作与状态反馈，不引入新导航或重设计。
- [x] PRD 与验证：规则与服务测试、交互测试、构建、类型检查、1920×1080 浏览器验收。

边界：上级撤回指派或变更导致审批冲突；无本人指派；重复承接/提交；审核退回保留申请；非本人 A 不可编辑；计划时间不得重写；预计日期不作为实际完成日期；历史旧结构只读关联兼容，不批量改写。

## 验证结果

- 9 个相关测试文件、88 个用例通过；覆盖既有工作区和表单、三级来源、审核差异与同步、API 层持久化、锁定原计划和列表/详情。
- TypeScript 全项目检查通过；Vite 构建通过，有既有大包提示。
- 浏览器 1920×1080：公司文本 O/KR、主管只见本人指派、同页 KR 指派本人后添加 A、第三条 KR 无商机模板已检查。
- PRD 校验受历史“字段类型”规则命中及注册表需求数量不一致阻挡；未扩大修改历史 PRD 注册表。
- 本仓库无后端。生命周期和数据写入沿用现有本地 Mock 持久化；远端模式需接入同等契约，未宣称线上跨用户、租户鉴权已完成。
- 工作区并存其他功能改动，相关路径 ownership 不独占，不创建 checkpoint，不推送。
