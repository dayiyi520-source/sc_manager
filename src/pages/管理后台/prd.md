# 管理后台 PRD（产品需求文档）

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档名称 | 管理后台产品需求文档 |
| 版本 | V1.0 |
| 产品形态 | 企业级 Web 管理后台，桌面端优先 |
| 依据 | 当前 React/TypeScript 页面、菜单配置、数据服务与现有交互 |
| 说明 | 未在现有页面确认的业务制度、指标口径和外部系统同步规则，标记为待确认 |

## 2. 背景与目标

管理后台用于统一承载员工工作、客户经营、产品研发、项目交付、综合事务和组织管理，减少业务数据分散、状态不可追踪和重复录入问题。

目标：

- 提供统一登录、导航、标签页和全局搜索入口。
- 让客户、线索、商机、投标、合同形成可追踪的经营链路。
- 让产品线、版本、任务、测试、缺陷和评审形成产研交付闭环。
- 让项目、里程碑、交付和运维任务具备明确负责人、状态和时间。
- 所有核心数据以服务端持久化结果为准，异常、空数据、权限和并发冲突可恢复、可解释。

## 3. 产品范围与菜单

| 一级菜单 | 二级功能 | 主要目标 |
|---|---|---|
| 工作台 | 我的任务、目标与绩效、知识库、协助事项 | 聚合个人待办、目标、知识和跨部门协助 |
| 客户与商机 | 数据看板、客户档案、线索、商机、拜访、跟进、合作伙伴、标讯、招投标、中标接洽、招标复盘、合同、售前任务 | 管理客户经营全流程 |
| 产研管理 | 产品线、版本迭代、产品任务、设计任务、研发任务、测试任务、缺陷管理、版本评审、复盘管理、产品规划 | 管理产品研发和质量交付 |
| 综合中心 | 审批、考勤、采购、资产、发票、回款 | 管理企业综合事务 |
| 项目管理 | 项目列表、里程碑计划、交付任务、运维任务 | 管理项目执行、交付和运维 |
| 系统与组织 | 团队组织、系统设置 | 管理人员、角色、配置和审计 |

## 4. 角色与权限

| 角色类型 | 典型权限 | 数据范围 |
|---|---|---|
| 普通成员 | 查看授权数据，创建和编辑本人草稿、本人任务结果 | 本人及参与记录 |
| 业务负责人 | 维护负责的客户、产品线、项目及任务 | 所负责业务范围 |
| 审批人/直属上级 | 查看管理范围数据、处理审批和复盘反馈 | 管理范围或流程节点 |
| 测试/研发/设计人员 | 处理被分配工作项、提交结果和证据 | 所属产品线、项目和任务关系 |
| 系统管理员 | 成员、角色、权限、系统配置、审计查询和高风险操作 | 租户全量 |

权限必须同时校验功能权限、数据范围、对象状态和版本。无权限时禁止通过直接地址访问，敏感客户、合同、回款和人员数据不得在无授权范围内展示。

## 5. 通用交互与业务规则

### 5.1 页面结构

- 登录后进入管理后台，左侧为分组菜单，顶部为用户、主题、搜索和页面标签。
- 页面支持加载中、正常、空数据、错误、无权限、禁用和提交中状态。
- 主要操作使用确认、成功/失败提示和局部刷新；禁止无反馈提交。
- 列表页面支持搜索、筛选、分页、行操作；是否提供批量操作以实际页面能力为准。
- 破坏性操作必须二次确认；删除、状态变化、审批、发布和批量操作需要审计记录。

### 5.2 状态和并发

服务端负责最终校验租户、权限、状态、版本、关联关系和幂等性。数据被其他用户修改时提示刷新后重试；批量操作需反馈成功、失败和未处理数量。父工作项存在子任务时，父项不允许绕过子任务规则直接完成；已发布版本和已关闭记录原则上只读。

## 6. 模块需求

### 6.1 工作台

| 功能 | 需求 |
|---|---|
| 我的任务 | 展示待处理、已完成、审批、客户和商机等聚合指标；点击指标进入来源列表；待办卡片展示标题、负责人、状态、截止时间。 |
| 目标与绩效 | 支持 OKR 周期、目标、关键结果、权重、进度、截止日期和工作关联；支持草稿、提交、复盘总结、反馈和查看状态。 |
| 知识库 | 支持分类、关键词、标签、收藏、排序、上传、详情预览和删除确认；文档删除保留审计。 |
| 协助事项 | 支持发起、受理、转派、处理中、待验收、关闭、驳回和搁置；负责人完成后由发起人验收，附件和处理记录可追溯。 |

### 6.2 客户与商机

| 功能 | 需求 |
|---|---|
| 数据看板 | 展示客户数、商机数、项目数、新增和成交等指标，以及趋势、漏斗、来源、贡献榜和流失分析；统计口径需与业务确认，生产环境不得使用演示数据。 |
| 客户档案 | 支持按名称、行业、负责人、等级和状态查询；维护客户基本信息、联系人、标签、跟进历史、商机和合同关联。 |
| 线索与商机 | 支持线索创建、分配、转化；商机维护金额、阶段、预计时间、赢单概率、负责人和协作人；阶段流转需校验前置条件。 |
| 拜访与跟进 | 记录拜访计划、签到、方式、时间、地点、纪要、下一步计划和附件；历史记录不可静默覆盖。 |
| 合作伙伴、标讯、招投标、中标接洽、招标复盘 | 支持对象列表、筛选、详情、阶段变化和关联客户/商机；审批、金额和外部同步口径待确认。 |
| 合同与售前任务 | 维护合同基本信息、履约、付款阶段及售前任务；关键金额和状态修改需要权限和审计。 |

### 6.3 产研管理

| 功能 | 需求 |
|---|---|
| 产品线 | 支持搜索、创建、负责人、成员、描述、网址、启停状态和统计；详情可进入版本、需求、任务、缺陷和成员设置。 |
| 版本迭代 | 支持版本列表、起止时间、负责人、状态、完成度、工时容量、需求/任务/缺陷关联和规划视图；发布前校验测试和评审规则。 |
| 统一工作项 | 产品、设计、研发、测试、缺陷、交付和运维任务统一展示标题、类型、优先级、负责人、状态、计划时间、关联对象、附件和动态。 |
| 测试与缺陷 | 支持测试任务、用例目录、用例编辑、批量操作、测试计划、执行结果、证据、缺陷关联和版本测试报告；缺陷可重开并保留历史。 |
| 版本评审与复盘 | 支持草稿、提交、评审意见、会议记录、附件、结论和复盘结果；提交后按权限只读。 |
| 产品规划 | 展示需求池、版本和规划关系；支持将合适需求纳入版本，并保留来源和操作记录。 |

### 6.4 综合中心

审批、考勤、采购、资产、发票和回款均提供列表、筛选、详情、状态和操作反馈。审批按当前节点授权处理；采购、发票和回款的金额、额度、核销和审批规则需业务确认后固化；历史记录默认不可物理删除。

### 6.5 项目管理

| 功能 | 需求 |
|---|---|
| 项目列表 | 支持按项目名称、客户、项目经理、交付阶段和健康度筛选；展示预算、进度、风险、健康度和关键操作。 |
| 里程碑计划 | 展示项目里程碑、计划起止、负责人、完成状态和延期风险；变更需要记录原因。 |
| 交付与运维任务 | 复用统一工作项字段和状态规则，支持负责人、计划时间、依赖、附件、评论和完成验收。 |

### 6.6 系统与组织

| 功能 | 需求 |
|---|---|
| 团队组织 | 按部门查看成员，支持姓名/职位/部门搜索、添加、编辑、启停；停用成员不能再被选为新的负责人，历史记录保留。 |
| 系统设置 | 支持基础设置、角色权限和审计日志；会话、备份、加密等高风险配置仅管理员可修改，并提示生效范围。 |

## 7. 异常处理

| 场景 | 处理 |
|---|---|
| 网络失败或超时 | 显示明确错误、保留当前输入并提供重试。 |
| 无权限 | 显示 403 状态，不泄露对象详情。 |
| 数据不存在/已删除 | 显示 404 或已删除提示，并提供返回列表入口。 |
| 字段校验失败 | 定位错误字段，说明格式、长度、必填和依赖关系。 |
| 并发冲突 | 提示数据已更新，要求刷新后重新编辑。 |
| 批量部分失败 | 展示成功、失败、未执行数量和失败原因，支持安全重试。 |
| 上传/保存失败 | 不提示成功，不丢失已填写内容，支持重新提交。 |

## 8. 验收标准

### 8.1 功能验收

- 登录、退出、会话失效和无权限访问行为正确。
- 六个一级菜单及其二级页面可按权限进入，标签页打开/关闭和刷新行为正确。
- 各列表的查询、筛选、分页、详情、编辑和状态操作与页面实际能力一致。
- 核心新增、编辑、审批、发布、验收和删除操作刷新后仍以服务端数据为准。
- 产品线、版本、工作项、测试、缺陷、项目和客户对象的关联关系可追溯。
- 所有失败、空数据、加载中、禁用、提交中和并发冲突状态均有可理解反馈。
- 高风险操作有权限校验、二次确认和审计记录。

### 8.2 性能与体验验收

| 项目 | 标准 |
|---|---|
| 首屏加载 | 常规网络下不超过 3 秒；加载期间显示骨架或 Loading。 |
| 列表查询 | 常规查询响应不超过 1 秒；大数据量采用分页，单页默认不超过 100 条。 |
| 提交反馈 | 用户操作后 2 秒内给出成功、失败或处理中反馈。 |
| 响应式 | 1920×1080 桌面视口布局完整，窄屏不遮挡主要操作。 |
| 视觉与可访问性 | 使用项目 Design Token；控件具备正常、悬停/聚焦、加载/激活和禁用/错误状态。 |

## 9. 待确认事项

1. 客户经营指标、金额、赢单概率和漏斗统计的正式口径。
2. 审批、采购、回款、发票和考勤的额度、节点及组织制度。
3. 云效、钉钉、企微、财务和考勤等外部系统的同步范围与频率。
4. 各角色的数据范围、字段级权限和跨部门查看规则。
5. 版本发布、测试通过、评审通过和项目验收的最终准入条件。
